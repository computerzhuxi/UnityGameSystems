# 可复用包规范

## 最小目录

    Packages/com.example.system
    ├─ Runtime/
    ├─ Tests/
    ├─ Samples~/
    ├─ Documentation~/
    ├─ README.md
    ├─ CHANGELOG.md
    └─ package.json

按需要在 Runtime 下建立 Core 和 Unity 层。每个物理源码根只归属一个 asmdef，避免程序集范围重叠。

## 公共接口

- 公共 API 只表达稳定能力，不暴露内部状态机或实现类型。
- 查询和命令应分离；观察者优先获得只读接口。
- 参数非法时应有明确行为，不依赖静默修正掩盖调用错误。
- 事件顺序、无变化行为、异常和重入规则必须写入 API 契约并有测试。
- 类型、字段或程序集迁移必须保护 Unity 序列化身份。

## 独立性验收

1. 运行时不引用具体游戏。
2. 在独立 Lab 中可以导入、测试和构建。
3. Sample 不依赖开发仓库之外的隐藏资产。
4. 包拥有自己的测试、说明和版本记录。
5. 消费项目只需安装或编写外部适配层，不修改包源码。

## 文档要求

每个包至少提供快速入门、边界、公共 API、版本变化和一个可运行示例。复杂包应补充架构、集成、迁移和故障排查文档。
