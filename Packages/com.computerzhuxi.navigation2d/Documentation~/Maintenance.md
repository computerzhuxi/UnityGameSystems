# 开发、验证与故障排查

只修改正式 Packages 源码，不修改 PackageCache。使用仓库 Navigation2DLab；Unity 版本按 Lab 的 ProjectVersion.txt。新增或修改方法遵守中文 XML 文档注释，关键设计分支说明原因。

运行仓库 `Tools/ValidateNavigation2D.ps1`；关闭目标项目编辑器后启动批处理。测试结果必须有非零测试数量、无失败，且保留失败尝试日志。发布前还需独立 Sample、空 Library、ARPG 集成、实际 DLL 图、真实资产恢复与人工观察。

|症状|检查|
|---|---|
|StartBlocked|角色实际占位与配置半径是否重叠障碍；不自动把角色推出墙|
|StartNotConnected|格距可能过粗，精确位置与中心被薄墙隔开；减小格距或修正场景|
|BudgetExceeded|先检查障碍域与目标；无限隐式网格不能有限证明所有不可达情况|
|看似没有障碍却失败|Trigger 策略、障碍层、物理场景是否正确|
|动态障碍未更新|确认物理同步时序；没有跨请求障碍缓存|
|路径正确但角色卡住|移动半径、碰撞体尺寸、路径点到达容差或强制运动通道是否一致|
|另一层的墙挡路|消费适配层是否只选择了当前已提交层的障碍|

不要从路径点之间跳过一个拐角后直接移动；跳点形成的新线段仍需 IsSegmentClear。扫掠安全只表示查询时刻的事实，实际物理运动仍需碰撞控制。

人工清单：Scene Gizmos 的路径/半径；薄墙绕行；窄道中不同半径；障碍开关与恢复；ARPG 巡逻、追击、目标移动与停止；楼梯中途返回和正式切层后的障碍隔离。未取得观察者确认时标记待验收。

候选阶段不提交、打标签或推送。独立复核通过并授权后，先发布包提交和不可变标签，再从远端标签独立安装验证，最后更新 ARPG manifest/lock 并复测。

## 0.2.0 Agent 排错

- 每帧新任务导致频繁查询：跟随移动目标使用 UpdateDestination，SetDestination 明确表示替换任务。
- 有路径但不走：纯 Agent/旧便利组件确认调用 Tick、未 Pause、dt>0；NavigationNavigator2D 自动推进但仍需要运动器消费 DesiredDirection，检查项目运动系统是否消费建议。
- 下一路径点在身后：正常连续运动已有回归；瞬移必须 InvalidatePath，不把传送当正常路径进度。
- 暂停仍移动：清除项目执行器速度；代理只清除建议。
- 动态封路短暂停顿：立即停走并等待剩余重算间隔属于设计；需要立刻重新规划的已知地图修改可显式失效。
- DomainUnavailable：检查项目正式层级和掩码，不要降级成全图无障碍。

人工新增项：Agent Lab 的移动目标、暂停/恢复、重置、障碍开关；ARPG 目标移动时持续追击无抖动，重算节流没有不可接受的迟钝；旧版人工验收不能冒充 0.2.0 确认。

## 群体避让排查

1. 自己阻挡自己：检查每批稳定 Id 唯一，外部物理查询排除自身；不要直接把所有 Actor 层加入路径障碍掩码。
2. 在另一个角色前停住：检查目标网格点是否位于身体内；启用 Agent 的安全前视，并检查 Infeasible/TruncatedNeighbors。战斗终点本身被占据需要项目分配站位。
3. 避让减速失效：不要 normalized 输出速度；将完整速度幅度交给运动器。
4. 墙旁等待：实际位移必须再次校验，地图裁剪后 ORCA 无理想保证；窄道不强制脱困。
5. 不同层互相避让：消费者应按物理场景与正式空间层映射 Group，不能以障碍 mask 替代层级身份。
6. 冻结/攻击身体不让路：仍作为 Locked 邻居；不要注销可见身体或让它承担一半修正责任。

支持边界以 API 的有限数值域为准；保存失败与性能测试日志，不把旧 Agent 验收算作新群体验收。

## 快速组件故障排查

只挂 NavigationNavigator2D 不移动是正常职责分工：检查运动器是否已安装、Kinematic / Simulated 是否配置、身体是否属于同一刚体、角色层是否误选为障碍。运行期 Inspector 显示错误和 LastResult；BudgetExceeded 不能解释为已证明不可达。配置可直接修改，无需编辑源码。

正式 Runtime 不提供移动组件。导航不走属于职责边界；QuickStart 示例适配器不构成生产契约，实际项目应提供自己的移动系统。
