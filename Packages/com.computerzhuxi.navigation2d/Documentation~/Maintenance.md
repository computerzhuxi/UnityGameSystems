# 开发、验证与故障排查

只修改正式 Packages 源码，不修改 PackageCache。使用仓库 Navigation2DLab；Unity 版本按 Lab 的 ProjectVersion.txt。新增或修改方法遵守中文 XML 文档注释，关键设计分支说明原因。

运行仓库 `Tools/ValidateNavigation2D.ps1`；关闭目标项目编辑器后启动批处理。测试结果必须有非零测试数量、无失败，且保留失败尝试日志。发布前还需独立 Sample、空 Library、ARPG 集成、实际 DLL 图、真实资产恢复与人工观察。

|症状|检查|
|---|---|
|StartBlocked|角色实际占位与配置半径是否重叠障碍；不自动把角色推出墙|
|StartNotConnected|格距可能过粗，精确位置与中心被薄墙隔开；减小格距或修正场景|
|BudgetExceeded|先检查障碍域与目标；无限隐式网格不能有限证明所有不可达情况|
|看似没有障碍却失败|Trigger 策略、障碍层、物理场景是否正确|
|动态障碍未更新|确认物理同步时序；没有跨请求障碍缓存|
|路径正确但角色卡住|移动半径、碰撞体尺寸、路径点到达容差或强制运动通道是否一致|
|另一层的墙挡路|消费适配层是否只选择了当前已提交层的障碍|

不要从路径点之间跳过一个拐角后直接移动；跳点形成的新线段仍需 IsSegmentClear。扫掠安全只表示查询时刻的事实，实际物理运动仍需碰撞控制。

人工清单：Scene Gizmos 的路径/半径；薄墙绕行；窄道中不同半径；障碍开关与恢复；ARPG 巡逻、追击、目标移动与停止；楼梯中途返回和正式切层后的障碍隔离。未取得观察者确认时标记待验收。

候选阶段不提交、打标签或推送。独立复核通过并授权后，先发布包提交和不可变标签，再从远端标签独立安装验证，最后更新 ARPG manifest/lock 并复测。
